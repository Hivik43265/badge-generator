# Этап 9 — Frontend (BG-Frontend)

## Что сделано
- **Главное окно**: в центре вкладки «Макет» / «Предпросмотр». Записи вынесены в нижний док `dock_records`, панель макета — в правый док `dock_layout_panel`. Доки можно перемещать, откреплять и закрывать. В меню «Вид» есть переключатели панелей и пункт «Вернуть расположение панелей». `saveState`/`saveGeometry` пишутся в QSettings (`window/state`, `window/geometry`) при закрытии и восстанавливаются при запуске.
- **Выбор строки в таблице** сразу перерисовывает холст: `layout_editor.set_person(pid)` → `render_card(pid, side)`. Предпросмотр синхронизируется с выбором.
- **Шаблон пустой**: UI не создаёт демо-макет. На пустом холсте показана подсказка «Добавьте элементы с панели инструментов». Это оформление редактора (элемент сцены), в рендер оно не попадает. Подсказка скрывается, как только появляется хотя бы один элемент.
- **«Добавить элемент»**: 9 кнопок на панели, те же действия на панели инструментов «Элементы» и в меню «Элементы». Действия применяются к текущей стороне, переключатель стороны тоже вынесен на тулбар. Кнопки: Текст, Текст из поля (выбор поля), Изображение (выбор файла, путь относительно base_dir), Фон стороны (`set_background`: цвет, изображение или сброс), Фото из базы, Рамка, Линия (`create_element(type='line')`), Штрихкод, QR-код. Новый элемент создаётся по центру холста (`x=(1011-w)//2`, `y=(638-h)//2`) с z поверх остальных, сразу выделяется и доступен в свойствах.
- **Свойства элемента**: X, Y, ширина, высота, слой, поле записи, значение или путь, шрифт (pt), цвет, заливка, цвет и толщина рамки, символика штрихкода, а также сырой JSON стиля. Видны только поля, применимые к типу элемента. Есть кнопки «Выше» / «Ниже» (z_order ±1) и «Удалить элемент».
- **QR и штрихкод показаны** по финальному решению Архитектора. Флага SHOW_QR, пометок «не в v1» и заглушек нет. Превью — только через `render_card`.
- `backend_api.ELEMENT_TYPES`: добавлен 'line', `V1_TYPES` удалён. SQL в ui/ по-прежнему нет, проверка D7 зелёная.

## Требует подтверждения Backend
- Ключ символики штрихкода — `style["symbology"]` со значениями `"code128"` / `"ean13"` (по умолчанию code128). В README этот ключ пока не описан.
- 'line': схема Backend теперь v3 (LATEST=3), тип принимается, поэтому тест не пропускается. Тест оставлен толерантным: если Backend отклонит тип, он печатает `SKIP line: …` и ничего не подделывает.
- В смоук-тесте ожидаемая версия схемы заменена с 2 на `db.LATEST`, потому что Backend поднял её до 3.

## Тесты
- `QT_QPA_PLATFORM=offscreen .venv/bin/python ui/smoke_test.py` → **36 OK, ALL OK** (SKIP: 0).
- `.venv/bin/python -m pytest -q` → **254 passed, 10 warnings in 5.74s**. Один прогон перед этим дал 1 failed (`tests/test_stage10.py::test_qr_ec_levels_and_invalid`, Backend). Отдельно этот тест прошёл, повторный полный прогон зелёный. Видимо, Backend в этот момент правил код, но тест стоит проверить на нестабильность.

Новые проверки этапа 9 в смоук-тесте:
- выбор строки → `canvas_image == render_card(pid)`, предпросмотр синхронизирован;
- пустая БД → 0 элементов, подсказка видна, рендер не содержит подсказку;
- каждая кнопка → `create_element` с верным типом, по центру, элемент выделен;
- фон → `set_background`/`get_background`;
- свойства: шрифт, цвет, поле, symbology; z-order ↑↓; удаление;
- доки: перенос влево и скрытие → закрытие → новое окно с временными QSettings восстанавливает расположение; «Вернуть расположение» возвращает исходное.
