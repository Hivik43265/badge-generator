# Этап 4 — Frontend: подключение к реальному Backend

Код: `ui/` и `main.py`. Файлы `badge_backend/`, `data_tools/` и `.venv` не изменялись, пакеты не ставились: всё нужное (PyQt6, Pillow, openpyxl) в .venv уже было.

## Архитектура
- `ui/backend_api.py` — единственный адаптер, тонкие вызовы `badge_backend.api`. В нём нет хранения данных в памяти, нет SQL и нет рисования (QPainter-заглушка удалена). Адаптер держит соединение `api.connect(db_path)` и `base_dir` (каталог БД). Рендер переводит PIL.Image → QImage (`pil_to_qimage`, только конвертация). `run_export()` открывает своё соединение для фонового потока.
- `ui/main_window.py` — меню «Файл»: Открыть БД…, Импорт…, Экспорт…, Печать…, Выход; панель инструментов; строка состояния (БД и база путей фото). Путь к БД хранится в QSettings, по умолчанию `<корень>/project.db`.
- `ui/records_table.py` — колонки из `list_fields()` плюс чекбокс «Печать» (`update_person(print_mark=…)`); поиск, сортировка, кнопки «Добавить», «Изменить», «Удалить», «Отметить все», «Снять отметки» (`mark_printed`).
- `ui/record_form.py` — поля записи, фото (путь относительно base_dir), photo_config: масштаб, смещение, обрезка (px), поворот по часовой. Живое превью: `render_preview` по несохранённому черновику. При сохранении `create_person`/`update_person` и `update_photo_config` вызываются только для этой записи.
- `ui/layout_editor.py` — холст 1011×638 px, фон — рендер Backend пустого шаблона. Рамки элементов можно перемещать мышью, размер меняется за угловой маркер. Свойства: type, x, y, w, h, z_order, field_name, static_value, style (JSON). Изменения пишутся через `update_element`/`create_element`/`delete_element`. Есть переключение «Лицевая»/«Оборотная».
- `ui/preview.py` — только вывод `render_preview`: запись, сторона, масштаб.
- `ui/dialogs.py` — ImportDialog: файл, сопоставление колонок (авто через `map_headers` или ручной выбор), папка фото, `import_file`, отчёт added/skipped/errors. ExportDialog: PNG или PDF, стороны, записи (отмеченные / выделенные / все), путь; QThread-воркер и прогресс-бар.
- Печать: QPrintDialog → выбор сторон → `badge_backend.services.print_service.print_cards` (через `api.print_cards`), печатаются только записи с print_mark=1.

## Несоответствия и вопросы к API
1. В README нет пути к БД по умолчанию. Взят `project.db` из примера (`<корень>/project.db`).
2. `import_file(mapping=…)` принимает только `{field: [заголовки]}`. Колонку нельзя явно исключить, поэтому в UI есть только «авто» или переназначение.
3. При ручном переназначении колонки `person_fields.label` остаётся исходным заголовком (например, «Комментарий» для ключа department). Если поле уже существует, label не обновляется (ON CONFLICT DO NOTHING).
4. Валидатор data_tools отклоняет строки без фото (PHOTO_MISSING → skipped). Нужно подтвердить, что это ожидаемое поведение.
5. sqlite3-соединение привязано к потоку, поэтому экспорт в QThread открывает своё соединение по db_path. БД `:memory:` для фонового экспорта не поддерживается.
6. У export_png/export_pdf нет колбэка прогресса. PNG экспортируется по одной записи (прогресс по записям), PDF — одним шагом.
7. Элементы qr/barcode создаются, но рендер v1 их пропускает (warning).
8. Для живого превью в `render_preview` передаётся dict-черновик с `fields_json` (не `fields`). Работает, но формат стоит закрепить в API.

# Этап 5 — Frontend: переход на исправленное API (stage-4-backend-api-fixes)

Изменено только `ui/`. В `badge_backend/`, `data_tools/`, `.venv` и `main.py` правок нет. Скриншоты и рендер теперь пишутся в `reports/`, в корне проекта ничего не создаётся: смоук-тест не пишет байткод, а QSettings хранит во временной папке.

## Что изменено
1. **Импорт** (`ui/dialogs.py: ImportDialog`):
   - mapping в формате `{"Заголовок": "field" | None}`: в выпадающем списке «авто», «— не импортировать —» (None) или поле;
   - третья колонка «Заголовок в таблице» передаётся как `labels`;
   - галочка «Требовать фото» (`require_photo`, по умолчанию выключена);
   - QProgressDialog подключён к `progress`, кнопка «Отмена» возвращает False;
   - в отчёте показываются errors, `warnings` и `cancelled` («изменения откатаны»).
2. **Экспорт и печать:**
   - в GUI-потоке `missing_photos(ids)`. Если такие записи есть, пользователь видит их список и подтверждает; при «Да» передаётся `allow_missing_photo=True`;
   - затем в GUI-потоке `snapshot(ids, sides)`, после чего `SnapshotWorker` (QThread) вызывает `export_png_from_snapshot`, `export_pdf_from_snapshot` или `print_snapshot`;
   - QProgressDialog с отменой: progress возвращает False;
   - обрабатываются `MissingPhotosError`, `.missing_photo_ids`, `.cancelled` и `None` (PDF отменён).
   - Своё соединение для потока (`run_export`) удалено, `:memory:` работает. Путь по умолчанию: `api.default_db_path(<корень>)`.
3. **Редактор макета:**
   - qr и barcode убраны из палитры «Добавить», в списке типа они неактивны с пометкой «(не в v1)»;
   - пересечения проверяет `find_overlaps` по тому же правилу, что в `tests/test_text_fit.py`: подложка rect с меньшим z_order не считается. Пересекающиеся элементы подсвечиваются красным, в панели и в строке состояния появляется «Внимание: элементы пересекаются (#a×#b)».
4. **Смоук-тест:** элемент «Гость» сначала ставится в (610,40,360×70), и тест проверяет предупреждение о пересечении с текстом шапки. Потом элемент **переносится** в свободную зону **(40, 556, 300×56)**: под фото, слева от полей, над нижней полосой. Тест проверяет, что он не пересекается ни с одним из остальных 9 элементов лицевой стороны, включая подложки rect, и не выходит за 1011×638. Добавлены тесты на предупреждение о пересечении, сценарий с отсутствующим фото (Нет/Да) для экспорта и печати, отмену через прогресс (импорт, PDF, PNG, печать) и экспорт из `:memory:`.
